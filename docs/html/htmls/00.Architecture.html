Architecture

System architecture, data flows, and module responsibilities for HyperSpec.

v2 · Updated 2026-05-26 · CLI Assets Skills

Overview

HyperSpec has two distinct runtime targets sharing one repository:

Node.js CLI src/ → dist/

TypeScript compiled with tsup to ESM. Handles project init, manifest indexing, component scanning, dev serving, translation prompts, and skill installation.

Browser Assets assets/

Vanilla JS/CSS shipped as-is. Injected into every generated HTML document. Provides the annotation system and the index portal.

Module Responsibilities

CLI CLI Modules src/cli/

Module Entry Function Purpose
index.ts program.parse() Commander setup, registers all commands
init.ts runInit(root) Creates docs/html/ structure, copies assets
index-cmd.ts runIndex(root) Runs indexer, writes manifest.json
setup.ts runSetup(root) Interactive config wizard, component scanning
serve.ts runServe(root, opts) HTTP server + SSE live reload via chokidar
translate.ts runTranslate(root, file, opts) Prints translation prompt for agents
install.ts runInstall(agent) Copies skill files to agent-specific locations

LIB Library Modules src/lib/

Module Exports Purpose
config.ts HyperSpecConfig, loadConfig, saveConfig, getDefaultConfig Config schema, persistence, defaults with partial merge
manifest.ts DocumentMeta, ManifestDocument, Manifest, extractMetadata, generateManifest HTML metadata parsing, manifest generation with translation linking
scanner.ts ScanResult, scanComponents CSS class / JS custom element extraction, markdown reference generation

Asset Modes

Each generated HTML operates in one of two modes set by hyperspec.config.json:

default

Reference Mode

<link> and <script> reference local asset files. Lighter HTML, shared assets, works with GitHub Pages and hyperspec serve.

<link rel="stylesheet" href="../assets/annotate.css">
<script src="../assets/annotate.js"></script>
optional

Inline Mode

CSS/JS embedded directly in the HTML. Self-contained single file, works for email sharing or S3 upload.

<style>
  /* annotate.css content embedded here */
</style>
<script>
  /* annotate.js content embedded here */
</script>

Component Library Integration

Optional

When a user runs hyperspec setup and provides a component library path, the following integration process is triggered.

1

Scan components

scanner.ts parses CSS for class selectors, JS for customElements.define() calls

2

Write reference

Results written to components/COMPONENT-REFERENCE.md

3

Update config

Config updated with component file paths

4

Agent reads reference

Agent skill reads the reference file and prefers registered components during HTML generation

5

Flexible extension

Agent still creates custom elements freely for anything the library does not cover

Multi-Agent Support

The HTML output and annotation JSON are agent-agnostic. Only the skill/instruction files differ per agent platform:

Agent Skill Format Install Location
Claude Code SKILL.md + commands/*.md ~/.claude/skills/hyperspec/
Codex AGENTS.md Project root
Antigravity skill.md .antigravity/skills/
Agent-Agnostic Design

Because HyperSpec output is standard HTML with a JSON metadata block and localStorage-backed annotations, any AI coding agent can participate in the generation and feedback cycle without modification to the core system.

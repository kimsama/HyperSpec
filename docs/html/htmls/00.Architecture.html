HyperSpec Architecture

System architecture, data flows, and module responsibilities. CLI Assets Skills

Overview

HyperSpec has two distinct runtime targets sharing one repository:

Node.js CLI src/ → dist/

TypeScript compiled with tsup to ESM. Handles project init, manifest indexing, component scanning, dev serving, translation prompts, and skill installation.

Browser Assets assets/

Vanilla JS/CSS shipped as-is. Injected into every generated HTML. Provides the annotation system and the index portal.

When an agent receives the /hyperspec command:

  1. Read hyperspec.config.json for assetMode and components settings
  2. Read COMPONENT-REFERENCE.md if a component library is registered
  3. Generate rich HTML with tables, SVG diagrams, code blocks, interactive elements
  4. Inject <script id="hyperspec-meta"> metadata block
  5. Inject annotation module (reference links or inline, per assetMode)
  6. Save to htmls/<filename>.html
  7. Run hyperspec index → manifest.json updated
  8. Portal (index.html) reads manifest at load time — new doc appears automatically

The annotation → feedback → revision cycle:

The feedback JSON omits DOM positions — agents locate content by selectedText + section heading, which is robust across HTML regeneration.

The hyperspec index command scans htmls/ and builds manifest.json:

Input: File System

htmls/
  auth-spec.html       (en, v2)
  api-review.html      (en, v1)
  ko/
    auth-spec.html     (ko, v1)

Output: manifest.json

{
  "documents": [
    {
      "path": "auth-spec.html",
      "locale": "en",
      "version": 2,
      "translations": {
        "ko": "ko/auth-spec.html"
      }
    }
  ]
}

Translation linking matches files in locale subdirs (ko/auth-spec.html) to top-level sources (auth-spec.html) by filename. When source version > translation version, the portal marks the translation ⚠ outdated.

Browser Assets assets/

annotate.js ~710 lines

Annotation IIFE: selection detection, floating toolbar, popover, side panel, localStorage persistence, structured JSON export to clipboard.

annotate.css ~515 lines

All annotation UI styles: toolbar, popover, 4 highlight types (comment/modify/delete/insert), side panel, export button, toast, responsive.

base.css ~120 lines

Typography, layout, CSS variables (--hs-*) for generated documents.

portal/* ~370 lines

Index portal: HTML shell, JS IIFE (manifest fetch, card render, search/filter/locale), CSS styles.

Asset Modes

reference (default) — link local asset files 
<link rel="stylesheet" href="../assets/base.css">
<link rel="stylesheet" href="../assets/annotate.css">
<script src="../assets/annotate.js"></script>

Lighter HTML, shared assets. Works with GitHub Pages and hyperspec serve.

inline — embed CSS/JS directly in HTML 
<style>/* base.css + annotate.css inlined */</style>
<script>/* annotate.js inlined */</script>

Self-contained single file. Works for email sharing, S3 upload, standalone distribution.

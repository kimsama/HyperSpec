User Project Output Structure

What hyperspec init does

Running hyperspec init scaffolds a docs/html/ directory inside the user's project. It copies the portal page, browser assets, and creates an initial configuration file and empty manifest. The htmls/ subdirectory is where generated HTML documents are placed by the agent.

project/
└── docs/html/
    ├── index.html                 # Portal page (copied from assets/portal/index.html)
    ├── manifest.json              # Document index (generated by `hyperspec index`)
    ├── hyperspec.config.json      # Project configuration
    ├── assets/                    # Copied from HyperSpec package
    │   ├── annotate.js
    │   ├── annotate.css
    │   ├── base.css
    │   ├── portal.js
    │   └── portal.css
    ├── components/                # Empty; populated by `hyperspec setup`
    │   ├── components.css         # (after setup with component library)
    │   ├── components.js          # (after setup with component library)
    │   └── COMPONENT-REFERENCE.md # (auto-generated by scanner)
    └── htmls/                     # Generated HTML documents
        ├── auth-spec.html         # (example)
        ├── api-review.html        # (example)
        └── ko/                    # Korean translations
            └── auth-spec.html     # (example)
Translation convention

Translations live in locale subdirectories under htmls/. The indexer links them to source documents by matching filename. For example, htmls/ko/auth-spec.html is automatically linked as the Korean translation of htmls/auth-spec.html.

Key Dependencies

HyperSpec has a minimal dependency footprint. Runtime dependencies handle CLI parsing and file watching; all other packages are development-only.

Package Version Purpose Type
commander ^14.x CLI framework — command parsing, options, help runtime
chokidar ^5.x File watching for hyperspec serve live reload runtime
typescript ^6.x Type checking dev
tsup ^8.x CLI bundling (src/ → dist/) dev
vitest ^4.x Test runner dev
@types/node ^25.x Node.js type definitions dev
Zero runtime deps for output

The generated HTML uses only vanilla JS/CSS — no frameworks, no CDN links, no build tools needed by end users. All browser assets are self-contained.

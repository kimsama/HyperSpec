# Architecture

## Overview

HyperSpec has two distinct runtime targets sharing one repository:

1. **Node.js CLI** (`src/` -> `dist/`) — TypeScript compiled with tsup to ESM. Handles project init, manifest indexing, component scanning, dev serving, translation prompts, and skill installation.

2. **Browser Assets** (`assets/`) — Vanilla JS/CSS shipped as-is. Injected into every generated HTML document. Provides the annotation system and the index portal.

```
User Project                          HyperSpec Package
┌─────────────────────┐               ┌──────────────────────┐
│ docs/html-spec/     │  hyperspec    │ dist/index.js (CLI)  │
│   htmls/*.html  <───┼── init ──────│ assets/ (copied)     │
│   assets/       <───┤              │ skills/ (installed)  │
│   manifest.json <───┤              └──────────────────────┘
│   index.html    <───┤
│   hyperspec.config  │
└─────────────────────┘
```

## Data Flow

### Generation Flow

```
Agent receives /hyperspec command
  -> reads hyperspec.config.json (assetMode, components)
  -> reads COMPONENT-REFERENCE.md (if components registered)
  -> generates HTML with:
       - rich content (tables, SVG, code blocks, interactive elements)
       - <script id="hyperspec-meta"> metadata block
       - annotation module injection (reference or inline per assetMode)
  -> saves to htmls/<filename>.html
  -> runs `hyperspec index` -> manifest.json updated
  -> portal (index.html) reads manifest.json at load time
```

### Feedback Loop

```
[1] Agent generates HTML
[2] User opens in browser, reviews
[3] User selects text -> annotation toolbar appears
[4] User adds comment/modify/delete/insert annotations
[5] Annotations stored in localStorage (per-document key)
[6] User clicks "Export Feedback" -> structured JSON to clipboard
[7] User pastes JSON into agent session (or /hyperspec-feedback)
[8] Agent parses JSON, reads source HTML, applies changes
[9] Version incremented, manifest re-indexed
[10] Back to [2]
```

### Manifest Indexing

```
htmls/
  auth-spec.html       (locale: en, version: 2)
  api-review.html      (locale: en, version: 1)
  ko/
    auth-spec.html     (locale: ko, version: 1)

          hyperspec index
               |
               v

manifest.json:
  documents:
    - path: "auth-spec.html", locale: "en", translations: { ko: "ko/auth-spec.html" }
    - path: "api-review.html", locale: "en", translations: {}
```

Translation linking: the indexer matches files in locale subdirs (`ko/auth-spec.html`) to top-level source docs (`auth-spec.html`) by filename. If the source version exceeds the translation version, the portal marks it outdated.

## Module Responsibilities

### CLI Modules (`src/cli/`)

| Module | Entry Function | Purpose |
|--------|---------------|---------|
| `index.ts` | `program.parse()` | Commander setup, registers all commands |
| `init.ts` | `runInit(root)` | Creates `docs/html-spec/` structure, copies assets |
| `index-cmd.ts` | `runIndex(root)` | Runs indexer, writes `manifest.json` |
| `setup.ts` | `runSetup(root)` | Interactive config wizard, component scanning |
| `serve.ts` | `runServe(root, opts)` | HTTP server + SSE live reload via chokidar |
| `translate.ts` | `runTranslate(root, file, opts)` | Prints translation prompt for agents |
| `install.ts` | `runInstall(agent)` | Copies skill files to agent-specific locations |

### Library Modules (`src/lib/`)

| Module | Exports | Purpose |
|--------|---------|---------|
| `config.ts` | `HyperSpecConfig`, `loadConfig`, `saveConfig`, `getDefaultConfig` | Config schema, persistence, defaults with partial merge |
| `manifest.ts` | `DocumentMeta`, `ManifestDocument`, `Manifest`, `extractMetadata`, `generateManifest` | HTML metadata parsing, manifest generation with translation linking |
| `scanner.ts` | `ScanResult`, `scanComponents` | CSS class / JS custom element extraction, markdown reference generation |

### Browser Assets (`assets/`)

| File | Size | Purpose |
|------|------|---------|
| `annotate.js` | ~710 lines | Annotation IIFE: selection detection, toolbar, popover, side panel, localStorage, export |
| `annotate.css` | ~515 lines | All annotation UI styles (toolbar, popover, highlights, panel, toast) |
| `base.css` | ~120 lines | Typography, layout, CSS variables for generated HTML documents |
| `portal/portal.js` | ~150 lines | Portal IIFE: fetches manifest.json, renders cards, search/filter/locale |
| `portal/portal.css` | ~200 lines | Portal styles (grid, cards, chips, search, responsive) |
| `portal/index.html` | ~20 lines | Portal HTML shell |

## Asset Modes

Each generated HTML operates in one of two modes set by `hyperspec.config.json`:

- **`reference`** (default) — `<link>` and `<script>` reference local asset files. Lighter HTML, shared assets, works with GitHub Pages and `hyperspec serve`.
- **`inline`** — CSS/JS embedded directly in the HTML. Self-contained single file, works for email sharing or S3 upload.

## Component Library Integration

Optional. When a user runs `hyperspec setup` and provides a component library path:

1. `scanner.ts` parses CSS for class selectors, JS for `customElements.define()` calls
2. Results written to `components/COMPONENT-REFERENCE.md`
3. Config updated with component file paths
4. Agent skill reads the reference file and prefers registered components during HTML generation
5. Agent still creates custom elements freely for anything the library doesn't cover

## Multi-Agent Support

The HTML output and annotation JSON are agent-agnostic. Only the skill/instruction files differ:

| Agent | Skill Format | Install Location |
|-------|-------------|-----------------|
| Claude Code | SKILL.md + commands/*.md | `~/.claude/skills/hyperspec/` |
| Codex | AGENTS.md | Project root |
| Antigravity | skill.md | `.antigravity/skills/` |

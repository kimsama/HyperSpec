# HyperSpec

Annotatable HTML document generation plugin for AI coding agents.

## Quick Reference

- **Build:** `npm run build` (tsup, outputs to `dist/`)
- **Test:** `npm test` (vitest, 24 tests across 6 files)
- **Dev:** `npm run dev` (tsup --watch)
- **Lint:** No linter configured yet

## Architecture

TypeScript CLI compiled with tsup (`src/` -> `dist/`) paired with vanilla JS/CSS browser assets (`assets/`). The CLI manages project scaffolding, manifest generation, component registration, and dev serving. Browser assets are plain JS/CSS shipped as-is — no build step for output.

### Key Modules

- `src/lib/config.ts` — `HyperSpecConfig` type, `loadConfig`/`saveConfig`/`getDefaultConfig`. Config lives at `docs/html-spec/hyperspec.config.json` inside user projects.
- `src/lib/manifest.ts` — `extractMetadata` parses `<script id="hyperspec-meta">` from HTML. `generateManifest` scans `htmls/` dir, builds `manifest.json` with translation linking.
- `src/lib/scanner.ts` — `scanComponents` parses CSS for class selectors and JS for `customElements.define()` calls. Returns `ScanResult` with `toMarkdown()`.
- `src/cli/*.ts` — Each CLI command is a separate file exporting a `run*` function. All registered in `src/cli/index.ts`.

### Asset Resolution

`init.ts` and `install.ts` need to find `assets/` and `skills/` at the package root. Since tsup bundles to `dist/index.js`, `__dirname` resolves to `dist/` at runtime. Both use a `resolve*Dir()` helper that tries `__dirname + "/../assets"` first, then walks up to find the directory — this makes the same code work in both compiled CLI and vitest contexts.

## Conventions

- Browser assets (`assets/`) are vanilla JS IIFE + plain CSS. No TypeScript, no modules, no build step.
- CLI code (`src/`) is TypeScript compiled to ESM.
- Each HTML generated by HyperSpec must include `<script type="application/json" id="hyperspec-meta">` with title, category, tags, dates, locale, version.
- Manifest paths are relative to `htmls/` dir (e.g. `"auth-spec.html"`, not `"htmls/auth-spec.html"`).
- Translations live in locale subdirs: `htmls/ko/filename.html`. The indexer links them to source docs by matching filename.

## Testing

Tests use vitest with temp directories (`mkdtempSync`). Each test creates an isolated temp dir, runs operations, asserts file outputs, then cleans up.

- `tests/lib/` — Unit tests for config, manifest, scanner
- `tests/cli/` — CLI command tests (init, index-cmd)
- `tests/integration/` — End-to-end flow tests
- `tests/fixtures/` — Sample HTML and component files

## Skills

Agent skill files live in `skills/`. These are markdown instruction files, not code:
- `skills/claude-code/` — SKILL.md + 3 slash commands (hyperspec, hyperspec-feedback, hyperspec-translate)
- `skills/codex/` — AGENTS.md
- `skills/antigravity/` — skill.md
